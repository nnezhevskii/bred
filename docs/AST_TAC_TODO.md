## Как воспроизводить

Bred-примеры передаются строкой в существующий `TACCompilerImpl.compile`. Он выполняет подготовку, анализ и lowering. Для просмотра инструкций достаточно такого Kotlin-кода с подставленным Bred-фрагментом:

```kotlin
import org.nnezh.org.nnezh.compiler.TACCompilerImpl
import org.nnezh.org.nnezh.ICGenerator.PrettyPrinter

val source = """
    type Flag = Off | On
    fun f(Off: Int): Int { return Off }
""".trimIndent()

val instructions = TACCompilerImpl().compile(source)
println(PrettyPrinter().format(instructions).joinToString("\n"))
```

Для G-99 и G-102 нужно остановиться после анализа. Следующий помощник использует существующие API и возвращает дерево, контекст и факты того же pipeline. Его можно поместить в будущий тест со стандартными зависимостями модуля tac.

```kotlin
import arrow.core.getOrElse
import org.nnezh.SemanticAnalyzer
import org.nnezh.SemanticAnalysisResult
import org.nnezh.bred.ast.AbstractSyntaxTreeBuilder
import org.nnezh.bred.ast.ProgramRoot
import org.nnezh.bred.ast.cloneSubtree
import org.nnezh.bred.codegenerator.TemplateInstantiator
import org.nnezh.bred.context.ProgramContextCollector
import org.nnezh.bred.context.ProgramGlobalContext
import org.nnezh.bred.context.ProgramTypeResolver
import org.nnezh.lexer.Lexer
import org.nnezh.org.nnezh.ICGenerator.LLTACGenerator

fun prepareExample(source: String):
    Triple<ProgramRoot, ProgramGlobalContext, SemanticAnalysisResult> {
    val tokens = Lexer(source).tokenize()
        .getOrElse { error("Lexer: $it") }
    val parsed = AbstractSyntaxTreeBuilder().build(tokens)
        .getOrElse { error("Parser: $it") } as ProgramRoot
    val initialContext = ProgramContextCollector().collect(parsed)
    val resolved = ProgramTypeResolver(initialContext).resolve(parsed)
        .getOrElse { error("Resolution: $it") }
    val context = ProgramContextCollector().collect(resolved)
    val instantiated = TemplateInstantiator(context).instantiate(resolved)
        .getOrElse { error("Instantiation: $it") }
    val finalContext = ProgramContextCollector().collect(instantiated)
    val finalRoot = ProgramTypeResolver(finalContext).resolve(instantiated)
        .getOrElse { error("Final resolution: $it") }
    val analysis = SemanticAnalyzer(finalContext).analyzeWithResult(finalRoot)
        .getOrElse { error("Semantic analysis: $it") }
    return Triple(finalRoot, finalContext, analysis)
}
```

**Граница ответственности.** parser → analyzer → tac.

### G-97 · P1 · Сохранять сигнатуру и вид цели при отбрасывании результата

- [ ] Исправить и закрепить регрессией.

**Основание.** Воспроизведённый дефект, контракт `4.4 и предыдущая проверка конструктора.

**Пример.**

```bred
fun g(): Int { return 7 }
fun f() { g() }

// Второй самостоятельный случай
type Pair(x: Int)
fun makeUnused() { Pair(readInt()) }
```

**Что происходит.** В первом случае CALL помечен g:Unit вместо g:Int. У отброшенного конструктора отсутствует destination, по которому C backend распознаёт продукт. В прежнем случае Pair(1) получен C-вызов Pair(...). Сценарий с readInt добавляет проверку однократности эффекта.

**Критерий готовности.** Передавать выбранную цель, её реальный тип результата и необязательный destination независимо друг от друга. Проверить g:Int без места записи и допустимое понижение конструктора с одним вызовом readInt.

**Граница ответственности.** analyzer → tac, common; адаптация c-backend.

### G-99 · P2 · Связать финальный AST, context и analysis одной версией программы

- [ ] Исправить и закрепить регрессией.

**Основание.** Воспроизведённая незащищённость прямого API, контракт `4.6. Штатный pipeline использует согласованное дерево.

**Пример.**

```kotlin
val (root, context, analysis) = prepareExample(
    "fun f(x: Int): Int { return x + 1 }"
)
val copied = cloneSubtree(root)
check(copied == root)
check(copied !== root)
LLTACGenerator(
    typeTable = analysis.expressionTypes,
    globalContext = context
).build(copied)
```

**Что происходит.** Равная копия AST не имеет ключей в старой IdentityHashMap. Вызов бросает missing semantic type for expression x + 1. Действующий API позволяет собрать эту комбинацию.

**Критерий готовности.** Передавать проверенную программу единым результатом подготовки, обозначить владение и запретить незаметную замену её частей. Копирование после анализа должно инвалидировать факты либо требовать повторного анализа. Контроль — исходное дерево работает, копия со старой analysis получает предметную ошибку принадлежности.

**Граница ответственности.** оркестратор, analyzer → tac.

**Основание.** Риск прямого API по чтению кода, отдельный сценарий ниже ещё не запускался. Контракт `6.

**Пример.**

```kotlin
val (root, context, analysis) = prepareExample(
    "type S = A | B fun f(s: S) {}"

    typeTable = analysis.expressionTypes,
    globalContext = context

```

**Критерий готовности.** Перед lowering проверять согласованность конкретных объявлений и их metadata, закрыть произвольную мутацию контекста проверенной программы. Диагностика называет отсутствующий тип. Явно различать оставшееся compile-time объявление и потерянное определение исполняемого типа.

## С какой задачи начать

Для одной короткой сессии подойдёт **G-96**: две функции, один вызов и очевидная проверка отсутствия переменной Unit. Можно сначала написать падающую проверку IR.

Для первого изменения контракта выбрать **G-93**. В нём проверяется весь путь от выбора параметра в анализаторе до конкретного RET. **G-99** можно начать независимо с объединения готовых результатов фаз. Перед общим pipeline **G-88** сохранить проверки поведения обеих точек входа.

**G-102 и G-101** описывают архитектурные проверки и рефакторинг. Их примеры не заявляются новыми найденными пользовательскими сбоями. У каждой карточки указано основание, чтобы приоритет опирался на реальные последствия.
