# Проверка backend Bred: от инструкции TAC до результата программы

Срез `09472ab`, 12 ноября 2026. Здесь собраны наблюдаемые дефекты и критерии исправления. Рядом — [архитектурный разбор Kotlin-модуля](C_BACKEND_ARCHITECTURE.md) и [разбор полученного C](GENERATED_C_REVIEW.md).

## Как проверялось

- `.\gradlew.bat :c-backend:test --offline --rerun-tasks` на JDK 25 — **17/17**. Это прямые тесты преобразования TAC в строки и диагностики ошибочных операндов. [CTranspileTest](../c-backend/src/test/kotlin/org/nnezh/compiler/CTranspileTest.kt)
- Небольшие программы переданы в `TACCompilerImpl.compile`, затем в `CTranspile.compile`. К выводу добавлен текущий `runtime.c`, как делает builder. Проверено **14 отдельных единиц трансляции** командой MSVC x64 19.51.36252 `cl /nologo /Od`. Собрались 5, остальные 9 вернули ошибку. Набор специально подобран по веткам риска; эта доля не оценивает частоту ошибок в программах Bred.
- Отдельно проверен публичный `BredToCCompilerFactory` со stdlib на копировании строки и `examples/3ac.bred`. Обе программы собраны с `/Od /W4` и запущены. Демо вывело три нулевые площади: его `square` явно возвращает `0.0` (G-84). Контрольная программа `f(7)` при `return x + 1` напечатала `8`. [Корневой API](../src/main/kotlin/org/nnezh/BredCompilationFactory.kt) · [Демо](../examples/3ac.bred)
- Для границы прямого Kotlin API отдельно поданы пустой IR и два намеренно неполных потока. Эти случаи показывают качество диагностики входа, а не достижимость из обычного Bred.

## Приоритет 1. Сборка проходит, результат теряет смысл

**1. ASSIGN строковой переменной копирует её имя.** Следующая программа должна напечатать `hello`. Обе проверенные точки входа дали `src`, процесс завершился с кодом 0.

```bred
fun main() {
    val src: String = "hello"
    val dst: String = src
    println(dst)
}
```

TAC передаёт источником переменную. В `parseInstruction(ASSIGN)` backend вызывает `asRightValue()` и при любом строковом destination оборачивает результат в кавычки. Получается `dst = create_string("src", strlen("src"));`. В отдельной функции с параметром `x` получено слово `x`. **Исправление:** различать `StringConst` и значение типа `String` до рендера. Литерал материализуется в runtime, готовая строка копируется по правилам представления. **Регрессия:** проверить литерал, копию из параметра, присваивание из другой переменной и вывод исполняемой программы. [ASSIGN](../c-backend/src/main/kotlin/org/nnezh/compiler/CTranspile.kt) · [Представление строки](../runtime.c)

**2. Длина глобальной строки не совпадает с байтами.** Для `val words: String[1] = ["é"]` и `println(words[0] + "!")` сгенерирован инициализатор `{"é", 1}`. В проверенной сборке содержимое stdout до CRLF — `C3 21`. При UTF-8 ожидается `C3 A9 21`. Kotlin `length` считает единицы UTF-16, `concat` копирует указанное число байтов. **Регрессия:** сравнить байты локального и глобального вариантов под явно выбранной кодировкой. Установить общий контракт для G-82. [renderGlobalInitializer](../c-backend/src/main/kotlin/org/nnezh/compiler/CTranspile.kt) · [concat](../runtime.c)

**3. Возврат локального массива создаёт адрес с истёкшим временем жизни.** Для `fun tokens(): Array<Int> { val a: Int[1] = [7] return a }` получен `int* tokens()` с `int a[1]; … return a;`. Проверен текст генератора. Полученный указатель после возврата не использовался. **Решение затрагивает язык:** различить возврат заимствованного аргумента, глобального массива и локального хранения. До появления модели владения можно диагностировать недопустимый возврат локального массива. Тест — диагностика до генерации C либо результат с явно заданным временем жизни. [Отображение результата функции](../c-backend/src/main/kotlin/org/nnezh/compiler/CTranspile.kt) · [Семантика массивов](type_system.md)

## Приоритет 2. Принятый исходник отвергает MSVC

| Минимальный случай | Наблюдение в C и диагностика | Где закрывать и как проверить |
|---|---|---|
| `type Outer(inner: Inner)` перед `type Inner(n: Int)` | Определение `Outer` содержит ещё неизвестный `Inner`. C2061. | Backend должен упорядочить ациклические типы по полям, хранящимся по значению. Проверить оба порядка и цепочку из трёх типов. Для цикла нужна отдельная диагностика G-73. |
| `fun f(switch: Int): Int { return switch }` | В прототип и тело скопировано `int switch`. C2143. | Отдельное отображение разрешённых идентификаторов в C-имена. Проверить также поле структуры и функцию с допустимым для Bred именем. |
| `fun main(user: Int) { println(intToString(user)) }` | Backend подменяет параметры на `size, arg`, тело читает `user`. C2065. | Определить допустимую сигнатуру Bred main. Отклонить неподдерживаемую сигнатуру либо явно передать аргументы из C-обёртки. |
| `val size: Int = 7` в `main` | `int size;` повторяет имя параметра обёртки. C2082. | G-69. Проверить программу с обычными именами `size` и `arg` после разделения Bred-функции и C-точки входа. |
| `val a: Int[0] = []` | `int a[0];`. C2466 и C2133. | Выбрать допустимое представление пустого массива либо ограничить цель до backend. Одной проверки «компилируется в TAC» мало. |
| `type Empty()` | `typedef struct Empty { } Empty;`. C2016. | При поддержке пустого продукта ввести целевое представление с допустимым размером; проверить объявление, создание и передачу в функцию. |
| `return a == b` для `String` | `var1=a==b;`. C2088. | G-81. Ввести реализацию сравнения по содержимому либо согласовать допустимые операции с frontend. Простая замена на `stringEquals` требует реального символа runtime (G-62). |
| `fun f() { return g() }` при `g(): Unit` | Получены `void var1; var1 = g(); return var1;`. C2182 и C2186. | Лишнее значение уже есть в IR. Исправление в TAC, контроль на границе backend и нативный тест. [Исходный разбор](TAC_REVIEW.md) |
| Исходник только с `type P(x: Int)` через TAC API | После typedef появляется отдельная `}`. C2059 ещё до линковки. `compile(emptyList())` также дал `["}"]`. | Закрывать тело только у открытой функции. Проверять единицу без main через компиляцию в объектный файл. Корневой API со stdlib добавляет функции и скрывает этот случай. |

## Приоритет 3. Контракт прямого входа 3AC → C

- **CALL читает предыдущие destination без проверки PARAM.** Из корректного TAC для `return g(1)` удалена единственная `PARAM`. Backend всё равно выдал `g(var3)`, взяв переменную из предшествующего `ASSIGN`. Получился внешне правдоподобный результат. Минимальная проверка — обнаружить разрыв группы аргументов и назвать индекс `CALL`. Долговременный вариант — передавать аргументы в самой модели вызова.
- **Оборванный STRUCT_DEF поглощается до конца входа.** Передача только `STRUCT_DEF P` и `FIELD n` дала `["}"]`. Документация обещает отказ на malformed struct definition. Завершение файла до `STRUCT_DEF_END` должно дать ошибку с именем типа и позицией начала.
- **Варианты суммы зависят от порядка метаданных.** По чтению кода: `SUM_VARIANT_FIELD` может первой создать вариант с тегом 0, а последующий `SUM_VARIANT` использует `getOrPut` и оставляет этот тег. Также `zip` при рендере конструктора обрезает несовпадающие списки полей и аргументов. Если формат требует фиксированного порядка и арности, проверять их при чтении. Обычный TAC-генератор выдаёт вариант раньше его полей. [Обработка метаданных](../c-backend/src/main/kotlin/org/nnezh/compiler/CTranspile.kt) · [Описанный контракт](3ac_to_c_generation.md)
